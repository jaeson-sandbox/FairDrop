- (direction) Owner authorizes roadmap item6 after connection recovery; create spec first, Sol implements, main reviews/verifies/integrates. Release publication remains a separate step.
- (capability) CAP-1: compose or paste bounded outbound text; success is a fresh code without clipboard reads/filesystem access and safe refusal of invalid input.
- (capability) CAP-2: intentionally reveal and copy exact normalized text; GET discloses no payload, one authorized POST reveals selectable inert text without scripts or clipboard API.
- (capability) CAP-3: Send Again, retry and waiting refresh preserve bounded RAM text with fresh identity; explicit exits forget it and stale work cannot resurrect it.
- (decision) Goal: desktop-to-browser short text or a URL, without creating a file. One text mode; URLs are inert text, never automatically classified, fetched, navigated or made clickable. Opposite direction and bidirectional clipboard sync are out of scope.
- (decision) Input: explicit "Send text" action from Idle opens a labelled multiline composer with Send and Cancel. Ordinary OS paste works; FairDrop never reads the clipboard. Maximum 65,536 normalized UTF-8 bytes. Normalize CRLF and CR to LF; otherwise preserve text including leading/trailing spaces, tabs and newlines. Reject blank/whitespace-only, invalid Unicode/unpaired surrogates, NUL and other C0 controls except TAB/LF (CR handled by normalization), and DEL. Blank means exclusively Unicode White_Space code points U+0009–000D, U+0020, U+0085, U+00A0, U+1680, U+2000–200A, U+2028, U+2029, U+202F, U+205F or U+3000 after normalization and control validation; use the same explicit predicate in Go and TypeScript, without trimming accepted content. Reject unpaired UTF-16 surrogates in the frontend before Wails serialization can replace them; test invalid UTF-8 directly at the Go App/coordinator boundary. Never silently truncate. Payload stays only in RAM; no temp file, cache, logs, mDNS content or snippet in metadata. UI rejects oversize edits explicitly without retaining an unbounded draft. Backend validates before making retained copies, with a 131,072 UTF-8 byte raw-size bound checked before normalization; input-byte count is not JS character count. Bound HTML expansion to six times payload cap plus 16KiB fixed chrome.
- (decision) API/domain: additive StageText(text) returns distinct TextMetadata {sessionId,byteLength,url,qrBase64,warnings}; payload never crosses back in metadata or events. Existing file/receive commands and DTOs compatible. Add invalid_text to the cross-language coded-error registry with fixed safe public copy; frontend field validation can explain blank, unsupported-character or byte-limit refusals specifically, without reflecting payload into backend error messages. Reuse single coordinator lease, activation, teardown and random session/token. Model text as an explicit mutually exclusive ServerStartRequest payload (not a file path or fake SourcePort). No filesystem calls for text. /text/{token} has its own literal coordinator/server/validator routing contract.
- (decision) Receiver: exact-token GET renders only fixed label and byte length plus "Read text" POST form, no payload, no claim. Exact-token POST atomically reserves and obtains coordinator authorization before an escaped HTML reveal. Same 404/423/refusal grammar as file sends, same no-store/no-referrer/nosniff/script-free CSP, no external resources. Render exact normalized text in a labelled readonly textarea with standard selection and browser/OS Copy instructions. This is the reliable plain-HTTP copy fallback: it works without JavaScript, secure-context Clipboard API or granted clipboard permission. No custom Copy button, no clipboard API call, no optimistic "Copied" claim, no clickable URL. Protect exact leading-newline and ampersand/closing-textarea/HTML parsing behavior with real DOM tests. Use html/template plain strings, never trusted HTML casts. Browser/OS may retain a viewed page; no secure-erasure promise.
- (decision) Completion means a verified full local HTTP response write and local HTTP finalization, not remote delivery, reading or copying. Set exact Content-Length and require a full write before finalizeAfterResponse; a short HTML write cannot complete. Reuse finalization and cancellation machinery; do not bypass finalized-write proof. Text UI says "Text sent" and does not invent file names, download sizes or copy confirmation. HTML response wire-byte progress may use existing backend accurate counters but UI must not label them as payload bytes; indeterminate text progress is acceptable.
- (decision) Lifecycle/UX: text is one live session, excludes file/drop/receive replacement while composing or staging/active; explain how to cancel. Support Send Again and retry through retained bounded immutable text + StageText with a fresh identity, and connection refresh for waiting text without source inspection. Extend recovery discriminated result explicitly with text. Explicit user Cancel/Done, dismissal, replacement and unmount clear draft/retained text references. Internal cancelImpl(true) lease release for Send Again preserves the remembered text until the fresh StageText attempt consumes it. Terminal/retained outcomes carry fixed label/status and scrub payload/capability. Keep draft after validation/setup refusal only while composer active so user can correct/retry; not after explicit Cancel. Keyboard focus, 44px controls, forced-colors, live error/fresh-code announcements follow Quartz.
