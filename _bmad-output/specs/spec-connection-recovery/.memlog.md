- (direction) Owner authorized continuing the roadmap after v1.6.0 on 2026-10-12. Implement connection recovery next, then text/link sharing separately. Spec first, Codex orchestrates and gpt-6-sol implements. Baseline 578a2910dc985bb89963d7719000e2a46808437d.
- (capability) CAP-1: a desktop user can inspect eligible local IPv4 endpoints for a waiting send or receive session and choose an alternative without changing OS settings; success is a fresh backend-validated candidate list without mutating the live endpoint.
- (capability) CAP-2: a desktop user can refresh a waiting connection with automatic or explicit network selection; success is old capability retirement before a newly validated session with fresh identity, URL and QR, preserving the selected sources or chosen receive folder.
- (constraint) Recovery must atomically refuse stale session IDs and any claimed/claiming/active/terminal session without cancelling it. Only the winning waiting-session operation can retire resources; no resource overlap, early replacement or false quiescence. Preserve bounded teardown and generation fences.
- (constraint) Preserve IPv4 eligibility and deterministic automatic ranking; explicit IDs must match fresh eligible interface/address pairs, never arbitrary IPs or unvalidated endpoint fallback. No mDNS token/path disclosure; all choices stay in process memory.
- (assumption) Lean recovery is user initiated through Trouble connecting in waiting views. No automatic network monitor, external connectivity probes, mid-transfer migration, resume, firewall changes or saved network preference. Existing automatic selection remains default.
- (constraint) Existing 10000-root lazy collection streaming and receive sink no-overwrite/download-marking/partial cleanup contracts remain unchanged. Receive folder may be retained privately only by the live backend session for revalidation during refresh; never disclose the path in DTOs or retain it after the lifecycle ends.
- (decision) Connection copy must say eligible/local rather than reachable/connected: interface enumeration cannot prove firewall, guest-network isolation or counterpart reachability. Failed refresh after retirement leaves no stale QR presented as usable and offers ordinary selection recovery.
- (decision) Code-grounded refinement supersedes raw receive-path retention: retain the already validated ReceiveDestination capability across waiting-only refresh after old server/handlers/drainer quiesce, transfer its ledger ownership exactly once, preserve existing sink identity checks at Save and close on cancellation or terminal failure. No new private receive path storage is needed. Send refresh revalidates current canonical roots through ordinary Stage machinery.
- (event) Coherence PASS: two dependent capabilities implement one waiting-session recovery goal; manual activation, atomic race ownership and before/after-retirement failures are explicit. Preservation PASS: all roadmap load-bearing requirements, current send/receive safety and resource contracts retained; only interface-selection non-goal is intentionally superseded. No unresolved intent questions. Owner standing approval permits Sol implementation after spec creation.
- (decision) Independent contract check clarified failure-path ownership: successful receive handoff requires old server/drainer quiescence; retirement failure instead bounded-closes the retained destination even if old work is unconfirmed, preserving its late-write fence, reports failure and never activates replacement. Keep a cancellation-addressable operation installed across old/new session handoff; lease alone cannot fence Cancel during an empty-session gap.
