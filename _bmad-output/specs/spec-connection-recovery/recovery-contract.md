# Waiting connection recovery contract

## Commands and network identity

Add `ListConnectionOptions(sessionID)` and `RefreshConnection(sessionID, networkID)` Wails commands. Keep existing StageTransfer, StageTransfers and StartReceive behavior and signatures. Empty networkID means Automatic; explicit IDs identify one eligible interface/address pair. Listing returns `{sessionId, currentAddress, choices: [{id, name, address}]}` with a non-null choices array. Names are bounded, display-safe interface labels, not SSIDs or hardware addresses. CurrentAddress is the session's advertised IPv4 address, even when no longer eligible. IDs are opaque to frontend; fresh enumeration and exact pair matching are authoritative. Deduplicate pairs and sort by the existing deterministic ranking. Automatic is always a UI choice, including when the eligible list is empty.

Refresh returns `{mode: 'send', send: FileMetadata}` or `{mode: 'receive', receive: ReceiveMetadata}`; only the corresponding metadata is present. Frontend validates the discriminated result and ordinary metadata. No absolute source/destination paths enter either command result. Extend the consumer-owned network contract through a small capability for read-only options and explicit endpoint selection; preserve existing NetworkPort callers and fake contracts. Listing must not call a mutating GetLocalIP or alter selected beacon identity. Explicit selection re-enumerates and refuses a vanished/ineligible pair with network_unavailable; never silently substitutes another network. An unsupported capability fails safely rather than ignoring the choice.

## Lifecycle and ownership

Coordinator atomically requires the exact nonempty current session ID, STAGED state and an available operation lease before reserving recovery. CLAIMING already excludes recovery, even before transfer-started reaches UI. If claim wins first, return a fixed busy/refusal without marking it cancelled or touching resources. If refresh wins, prevent old authorization before retiring its HTTP run. Do not call unconditional Cancel after checking state outside the lock. No external adapter calls under Coordinator.mu.

A fresh options/explicit-choice preflight may fail before retirement and leave the old waiting session intact. Recheck the live generation/state after external work. Once recovery starts retiring the old session, stop beacon and server and join the old drainer under existing bounds before starting anything new. An unproven cleanup bound blocks replacement and is a coded failure, never successful recovery. Cancellation/shutdown must fence the entire operation, including the interval between retirement and replacement. Avoid an unowned IDLE gap that admits unrelated Stage during recovery. Keep a cancellation-addressable session/operation installed continuously: holding the lease alone does not let Cancel mark an absent session. Test cancellation on both sides of the atomic ownership handoff.

Create a new immutable session ID and token. For send, copy current canonical root paths and revalidate through ordinary metadata admission; preserve lazy one-member collection preparation. For receive, the unclaimed session has saved no files. Keep its existing ReceiveDestination alive until old HTTP handlers and drainer end, then transfer destination-ledger ownership exactly once to the new session. Preserve existing sink identity checks and Close behavior; no new raw destination path storage, duplicate Close or writes during recovery. Successful handoff requires confirmed server/drainer quiescence. On any retirement failure, bounded-close the retained destination even if old HTTP work remains unconfirmed, preserving its late-write fence; report cleanup failure and never activate replacement. Any post-retirement failure/cancellation closes the retained destination. Generate the new URL/QR against the freshly selected address and new listener, with normal mDNS warning semantics.

Retirement emits an authoritative old-session reset before a new acknowledgment. A replacement failure leaves the old code invalid and the UI idle with a fixed actionable error. A pre-retirement refusal leaves the actual old state, including a winning active transfer, intact. Do not republish old metadata on failure or reset a later session through stale completions/events.

## Sender and receiver presentation

In the existing waiting/staged Trouble connecting disclosure, show current address, a labeled native select containing Automatic and eligible `name — address` choices, Reload networks and Refresh connection. Refresh uses the current selection; changing the select alone does not mutate a live session. No recovery controls appear during payload transfer or terminal outcome. New sessions default to Automatic; a successful refresh may retain its selected ID only for that live session. If it disappears after reload, show a fixed unavailable-selection message and require Automatic or another choice rather than silently switching.

The options list loads on demand, with loading/empty/error states and a retry. Duplicate list responses cannot overwrite a newer session or user selection; Cancel/unmount invalidates outstanding work. During refresh, expose busy status and prevent duplicate recovery or new selection. Hide/disable old QR, URL copy and open controls while retirement may be underway. Allow the ordinary Cancel action to abandon recovery safely. On success focus the waiting heading and announce that the new code replaces the old one. On failure follow authoritative lifecycle state; preserve an active transfer that won the race. Scope pending acknowledgments and early lifecycle events to the correct generation, as ordinary Stage does.

Use Quartz controls, keyboard labels, 44px targets, explicit programmatic focus styling and forced-colors outlines. Fixed copy explains that interface availability does not test firewall or guest-network isolation: both devices need the same local network. Never label a candidate Connected, Reachable or Verified. Update the current help wording that instructs users to cancel and select everything again. No settings persistence, external requests, periodic polling or OS configuration changes.

## Proof

Test pure deterministic enumeration, exclusion/deduplication, explicit stale choices and unchanged active selection. Force both claim/recovery race outcomes, stale/empty IDs, double refresh, Cancel/shutdown during teardown/rebuild, cleanup timeout and both send/receive replacement failures. Assert fresh identity, old-token rejection, exact payload bytes, no output before receive claim and destination Close ownership. Include meaningful mutation cases for authorization fences, cleanup-before-activation, explicit-choice validation, post-retirement stale-code removal and UI single-flight/stale responses. Existing native mutation inventory must still match and execute its named defenses.
