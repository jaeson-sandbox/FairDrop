updated: 2026-10-11T13:24

- (direction) Owner authorized roadmap item 3 after release 1.4.0: spec first, Sol implements, main orchestrates review and integration; subsequent intents remain out of scope.
- (capability) CAP-1: sender selects up to 16 local files/folders through native drops or accessible in-memory collection controls and sends them atomically in one session; a single selection preserves current direct-file or folder behavior.
- (capability) CAP-2: receiver previews collection count and logical size then explicitly downloads one streamed ZIP; Send Again and retry revalidate all remembered paths with fresh capability identifiers.
- (assumption) Conservative initial product choices: 16 selected roots; an optional keyboard-accessible selection list; multi-drop opens that list; archive FairDrop.zip with FairDrop/01-name and subsequent zero-padded ordinal prefixes to avoid cross-root collisions. Single-item flow stays immediate.
- (constraint) Reject invalid count before filesystem work; after admission resolve and inspect sequentially, reject canonical duplicates and ancestor overlaps, safe-integer aggregate overflow or any invalid source before networking. Preserve name warning policy, no-follow traversal, global 64 retained directory handles plus three transient handles across every prepared pin and active walk; selected files add at most 16 open content descriptors. Pin every member during all-or-nothing preparation; no deferred later-root preparation or second descendant index.
- (constraint) Collection and path list remain memory-only and defensively copied; nothing before Send starts a listener or reads payload. All acquired resources close on partial failure, cancellation, failed streaming or Close-before-WriteTo. One receiver and honest ZIP wire progress; failed ZIP is never finalized. No new features, dependencies or release in this slice.
- (decision) Selection contract derivation: keep StageTransfer singleton wrapper, add StageTransfers and SelectFiles; collection discriminator/count and basenames-only view; invalid_selection for zero/count/overlap, path_unsupported for unsafe aggregate size; no listeners before Send, preserve chooser generation/cancel/outcome recovery; numbered roots use existing sanitizer, nested portability warnings remain, and collection repeats preserve no persistent state. See selection-contract.md for these derived cross-layer details.
- (event) Coherence PASS: two dependent capabilities implement one collection handoff goal; scope, limits, archive namespace and ownership explicit. Preservation PASS: roadmap intent, all existing source/lifecycle invariants and accessible equivalent selection paths retained; initial 16-item/UI/naming choices are explicit assumptions, no unresolved blocking questions.
- (decision) Independent design review correction: preserve actual resolver generation-scoped busy until completion or bounded timeout; timed-out OS calls may persist. Directory Prepare uses current no-follow identity pin without staged size/mtime equality or re-enumeration; prepared files stream verified original descriptor across pathname replacement, while directory Walk refuses replacement. Supersedes stronger shorthand in earlier constraints; all other safety rules preserved.
- (decision) Naming edge correction from review: generated numbered archive root retains existing fallback and final trailing-dot/space trim, stays at most200 runes and255 UTF-8 bytes including ordinal, and truncates only on rune boundaries. Prefix must not turn an otherwise valid255-byte source basename into an unextractable258-byte name; nested name policy unchanged.
- (direction) Owner 2026-10-11: the 16-root cap was an agent assumption, not an owner choice; raise it to a 10,000-root sanity cap and ship as patch release 1.5.1 built from v1.5.0 (receiving stays unreleased), then merge forward into main.
- (decision) Supersedes the 16-root assumption: a collection admits 2..10,000 selected roots; 0 or >10,000 is invalid_selection before filesystem work. Archive member ordinals are zero-padded to max(2, digits(count)) (01-..16-, 001-..100-, 0001-..10000-) so names stay distinct and sort in selection order.
- (decision) Preparation becomes lazy per root to remove the count-dependent resource pressure: Stage still validates every root (existence, kind, no-follow, overlap, checked aggregate size) before networking, but files and folder pins are acquired one root at a time during streaming, so at most one top-level file descriptor and one prepared directory pin are retained at any moment, within the existing 64 retained + 3 transient handle budget.
- (decision) Trade-off accepted by owner: a root changed, replaced or removed after Stage now fails during the ZIP stream (aborted, never finalized) rather than before response headers; identity checks, no-follow rules, prepared-file descriptor verification and directory replacement refusal still apply per root at its own preparation. Singleton file and folder transfers keep their existing pre-header preparation.
- (constraint) Memory stays bounded by 10,000 selected-root records (no descendant index), one copy buffer and ZIP's required central directory. The editable selection list must remain usable at large counts (scrolling list, count shown out of 10,000).
- (event) Re-derivation for the 10,000 cap and lazy preparation: Coherence PASS (CAP-1/2 intact, constraints still bend design); Preservation PASS (all non-cap guarantees kept; superseded 16-root and all-before-headers rules recorded).
