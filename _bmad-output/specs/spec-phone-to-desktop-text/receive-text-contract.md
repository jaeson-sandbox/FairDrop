# Phone-to-desktop text contract

## Entry and desktop outcome

Idle gains **Receive text**, a secondary action alongside the existing Receive files action, outside the native drop zone. It starts a text-only session without any chooser, source inspection, sink/filesystem call or clipboard access. Existing file receiving and outbound text are unchanged. The waiting card names Text, shows the QR/link, and offers Cancel and existing connection recovery. Only one mode may be composing, staging or active at once. Reuse Quartz layout, 44px controls, heading focus, polite announcements, scripted-focus indicators and forced-colors outlines. Guard the QR against native dragging as existing cards do.

After complete acceptance, a held **Text received** outcome displays the accepted value in a labelled readonly, selectable multiline field and offers **Copy text** and **Done**. The field preserves exact normalized text, including a leading newline; URLs are inert, never classified, fetched, opened or made clickable. No payload is put into headings or live announcements. Copy goes through a new bound native command and says Copied only after success. A clipboard failure uses fixed safe copy, leaves the value available, and permits retry. Done clears the session and displayed value. Failed receive has a held fixed error outcome with Done and no partial text or Copy action. Cancellation clears the session; it does not retain a partial or cancelled text outcome. No automatic clipboard read or write.

## Input and HTTP

Use a separate literal `/receive-text/{token}` route, the existing random 128-bit capability and exact constant-time token match. Route is methodless with explicit GET/POST handling; wrong token, route, malformed path, HEAD and other methods get the generic 404. Valid requests against a spent claim get 423 while the listener lives.

An unclaimed GET is side-effect-free and displays a labelled editable textarea, the 64 KiB UTF-8 limit, **Send text**, and trusted-LAN guidance. Use a same-origin relative form action, POST, `application/x-www-form-urlencoded`, UTF-8 encoding and no scripts. The browser page works at 320 CSS pixels, supports native selection/paste, visible focus, light/dark and forced colors. Preserve receiver-page no-store, no-referrer, nosniff and script-free CSP headers on forms and result/error pages. Disable autocomplete where available; do not promise browser memory erasure. No payload in URLs, hidden fields, error pages or response echo.

The form must contain exactly one `text` body field and no extra or duplicate fields; do not merge URL query parameters into the submitted body. Content-Type must be application/x-www-form-urlencoded (optional UTF-8 charset only). Bound encoded body bytes to `3 * MaxRawTextBytes + 1024` before parsing, reading no more than cap+1. Reject declared oversize immediately; bounded chunked requests may be accepted. Do not use unbounded ParseForm/FormValue, multipart or filesystem staging. Invalid media/form/encoding/blank/control input returns a fixed 400 page; encoded oversize returns a fixed 413 page. Neither consumes the one-shot claim, retains text nor calls clipboard. A fixed retry link may return to the empty form; invalid submissions are not echoed. Interrupted/short bodies never commit. Use existing server request-read timeout/cancellation machinery to bound slow input; do not change file-transfer timeout contracts.

Reuse `NormalizeText`: 131,072 raw UTF-8 bytes checked before normalization; at most 65,536 normalized UTF-8 bytes; CRLF/CR to LF; all other accepted whitespace preserved. Reject invalid UTF-8, blank text by the existing explicit White_Space predicate, and unsupported controls. Never silently truncate. Do not use HTML maxlength as a byte limit or substitute rune/UTF-16 counts for UTF-8 bytes. Browser validation is advisory; the server owns all limits.

At most one POST may read/decode its body at a time per session, bounding aggregate request memory. A temporary processing reservation returns 423 to competing POSTs and releases on any preclaim refusal. After complete validation, atomically make the permanent one-shot claim and obtain normal coordinator authorization before committing the text. A later valid submission cannot overwrite it. Cancellation, shutdown, context expiry and recovery races must prevent stale authorization or commit, and obsolete work cannot resurrect a cleared session.

## Ownership, completion and clipboard

Model inbound text as an explicit mutually exclusive ServerStartRequest mode. The receiver-owned bounded RAM commit contract belongs to its consumer; keep implementations within existing transfer/server boundaries and do not misuse filesystem SinkPort or outbound SourcePort. Coordinator session identity/generation owns the accepted value. No text in Stage acknowledgements, metadata, progress/terminal events, diagnostics, discovery, retained history, disk, browser storage or logs. Length/status may be metadata; error messages are fixed. Clear backend and frontend references on Done, Cancel, replacement, failed setup and shutdown/unmount. Browser, Go and OS copies are not securely erased; copying intentionally leaves the OS clipboard alone when FairDrop clears its own state.

Add `StartReceiveText()` returning payload-free `ReceiveTextMetadata`, `GetReceivedText(sessionID)` returning a bounded value only for the current successful accepted receive, and `CopyReceivedText(sessionID)` which obtains that current value from the coordinator and writes through Wails ClipboardSetText. Do not widen the existing 2,048-byte CopyToClipboard link command or accept arbitrary frontend text in the new copy command. Empty, wrong, retired, uncommitted or cancelled IDs refuse. Clipboard writes admitted before a concurrent Done may finish; late responses must not alter a new UI/session or announce Copied. Never hold the coordinator mutex across the native clipboard adapter.

Receipt means the entire valid input was committed in RAM to the current authorized session. Only committed receipt may publish success. As with file receiving, a failed/lost phone acknowledgement does not undo the accepted desktop result; phone result copy says **Text received by this computer**, not saved to disk, copied or delivered to another app. Cancellation linearization and teardown bounds remain authoritative. Terminal events contain no value; desktop fetches through the session-guarded command and fences late values by request generation, session and mounted state. Account for the existing event-before-final-state-store ordering: a terminal notification must not trigger a transient false refusal while fetching the committed value. An unexpected value-fetch failure must show a recoverable fixed error, never an empty successful preview. Hold terminal receipt until Done, without the outbound three-second reset.

Waiting connection refresh reuses the existing recovery transaction with a distinct `receive-text` result and no file/receive/outbound metadata mixed in. It retires the old code, issues new identity and an empty text receiver, and keeps the selected eligible network semantics. Claim and recovery exclude each other; old POSTs or read/copy commands cannot target the replacement. No Receive Again or text history is added; Done then Receive text starts a fresh empty session.

Use literal route and value assertions and deterministic concurrency barriers. Test the entire browser form-to-desktop value seam with real form encoding, Unicode, CRLF and literal markup. Browser tests cover 320px, focus and forced-colors; native manual observations remain optional and unverified unless actually performed.
