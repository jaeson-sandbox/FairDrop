Accessibility review

review-accessibility.md

Not ready to claim WCAG 2.2 AA. Thirteen contract defects and two implementation-verification needs were identified.

criticalA11Y-01 · Three-second terminal reset is an inaccessible information timeout

Fix: Preserve a visible non-session outcome in Idle until next Stage or dismissal; do not force a second focus move.

highA11Y-02 · Light-mode non-text contrast fails

Borders measure 1.62–1.76:1; progress is 2.933531:1. Fix: Add ≥3:1 functional boundaries and revise progress colors.

highA11Y-03 · Focus, status, and alert compete

Fix: Define exactly one announcement owner per transition.

highA11Y-04 · Known-empty progress has no valid accessible semantics

Fix: Show “Empty file — 0 bytes to transfer” without a percentage progressbar.

highA11Y-05 · Stage Pending has no operable Cancel

Fix: Add Cancel preparation and local pre-ack cancellation authority.

mediumA11Y-06 · Assistive progress cadence is undefined

Fix: Decouple speech from visual updates; announce meaningful progress at most every five seconds.

mediumA11Y-07 · Cancel-pending and completion races lack feedback

Fix: Retain focus, expose “Canceling…,” and announce only the authoritative winner.

mediumA11Y-08 · Reflow/text-spacing floor is incomplete

Fix: Require vertical-only reflow at 320 CSS px, 200% text, and WCAG spacing overrides.

mediumA11Y-09 · Exact palette conflicts with forced colors

Fix: Make forced colors authoritative; exempt only tested QR rendering.

mediumA11Y-10 · Reduced motion omits indeterminate progress

Fix: Use a static pattern plus text and remove repeating movement.

mediumA11Y-11 · Unicode/bidi handling is underspecified

Fix: Use bidi isolation, grapheme-safe wrapping, and persistent full-name access.

mediumA11Y-12 · Firewall timing and focus return are undefined

Fix: Put guidance before Stage and restore focus after the OS prompt.

mediumA11Y-13 · Safe errors may be unusably generic

Fix: Make each safe message literal and actionable without color dependence.

mediumA11Y-14 · Native accessibility evidence matrix is missing

Fix: Record Narrator/NVDA and VoiceOver evidence for the full lifecycle and native prompts.

lowA11Y-15 · QR alternative needs exact semantics

Fix: Use concise non-token alt text, readonly URL text, and one semantic copy announcement.

Trust & cross-device handoff review

review-trust-cross-device.md

Revise before finalization. V1 scope is disciplined, but the consumer meaning of its bearer-link, network, receiver, and completion boundaries is incomplete.

highTCH-01 · Plain HTTP lacks a plain-language consequence

Fix: Explain that transfer traffic is not encrypted and may be observable on the network.

highTCH-02 · Single-use omits first-requester and preview risk

Fix: Explain first-opener ownership, require direct browser opening, and decide preview tolerance.

highTCH-03 · Firewall recovery is unresolved

Fix: Define platform-specific preflight, denial, focus, and help behavior.

highTCH-04 · Done overclaims iPhone Files state

Fix: Claim only sender-observable transport completion.

highTCH-05 · Receiver support lacks a validation matrix

Fix: Define and test supported browser/OS combinations before broad claims.

mediumTCH-06 · Copied URL lacks cross-device instruction

Fix: Say “Copy download link” and explain opening it in the receiving browser.

mediumTCH-07 · Different-network failure lacks recovery

Fix: Explain same Wi-Fi, guest isolation, cancellation, and fresh-link retry.

mediumTCH-08 · No-cloud/no-extra-copy benefit is ambiguous

Fix: State local sending and no extra FairDrop copy while acknowledging the receiver keeps the download.

mediumTCH-09 · AirDrop analogy overpromises parity

Fix: Keep it internal; external copy must name desktop sender, one browser receiver, same LAN, no account/app.

mediumTCH-10 · Generic receiver errors lack guided recovery

Fix: Accept the V1 limitation and add sender-side troubleshooting unless architecture changes.

mediumTCH-11 · Platform arrows imply symmetric native support

Fix: Spell out sender and browser-receiver roles; iPhone is receiver-only in V1.

lowTCH-12 · Working boards retain unsafe exploratory copy/QR visuals

Fix: Add exploration-only warnings or annotations and keep them non-normative.
