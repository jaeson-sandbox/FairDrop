- (decision) Adopt ports-and-adapters around a framework-independent Transfer Coordinator. It binds all phases and prevents Wails UI concerns, HTTP transport, discovery, streaming, and lifecycle state from becoming mutually dependent.
- (decision) main.go remains the composition root; app.go is a thin Wails adapter. The coordinator alone owns the transfer lifecycle and depends on internal ports implemented by network, server, and stream adapters.
- (decision) The Transfer Coordinator is the sole owner of lifecycle state. A mutex guards state and the current immutable session identity; external ports are never called while the mutex is held, and every asynchronous callback carries the session ID so stale callbacks are ignored. This binds FR8-FR14 and prevents races, re-entrancy deadlocks, and an old transfer mutating a new one.
- (decision) Use the externally visible states IDLE, STAGED, TRANSFERRING, DONE, and ERROR, plus an internal STAGING transition. Only IDLE may stage; cancel from STAGED or TRANSFERRING tears down and returns directly to IDLE; DONE and ERROR tear down before notification and reset to IDLE after three seconds.
- (decision) Stage exactly one regular file or one directory in v1. Reject zero or multiple paths with a typed user-facing error; never silently select the first item. This resolves the Phase 1 multi-drop mismatch without inventing a multi-root archive protocol.
- (decision) Each staged transfer owns a child context, cancel function, random session ID, server listener, beacon, reset timer, and immutable staged metadata. Stage is transactional: partial setup is unwound in reverse order; Cancel, terminal completion, and application shutdown invoke the same idempotent teardown.
- (decision) Stop operations for the HTTP server and mDNS beacon are idempotent and safe before Start, after failure, and when called repeatedly. Stop waits for owned goroutines to exit or returns a bounded shutdown error. This prevents double-close panics and leaked work.
- (decision) The HTTP endpoint is a one-shot capability URL using at least 128 random bits from crypto/rand in a raw base64url path segment. Only GET with the exact token may claim the transfer; invalid routes return 404, and later valid requests while claimed return 423. The claim is atomic and occurs before response headers.
- (decision) FairDrop v1 uses plain HTTP on a trusted LAN; it does not claim confidentiality against LAN observers. The capability token and filename are returned to the UI/QR but omitted from mDNS TXT records, which advertise only protocol version and a non-sensitive instance identity. TLS and authenticated native-receiver handshakes are deferred.
- (decision) The HTTP adapter sets Content-Disposition with a safe ASCII fallback plus RFC 5987 filename*, Cache-Control: no-store, Access-Control-Allow-Origin: *, nosniff, and Content-Length only for a regular file. It accepts no request body and applies bounded header/read-idle limits without a whole-transfer write deadline.
- (decision) File bytes are copied through a reusable bounded buffer and directory archives stream through io.Pipe. Cancellation must interrupt both filesystem reads and response writes; zip.Writer closes before the pipe writer. A stream error before headers becomes an HTTP error; after headers it is reported to the coordinator and aborts the handler with http.ErrAbortHandler so a truncated response is not presented as success.
- (decision) Stage preflights a path without persisting an index: reject symbolic links and non-regular special files, walk directories in constant memory to validate entries and compute display size, and revalidate during streaming. ZIP entry names are slash-normalized relative paths under one root and may never be absolute or contain '..' traversal.
- (decision) Progress is based on bytes successfully written to the HTTP response and throttled to at most four updates per second, with an unthrottled terminal snapshot. TransferStats retains numeric totalBytes and percent and adds totalKnown: directory streams use totalKnown=false, totalBytes=0, percent=0; zero-byte regular files use totalKnown=true. Speed is a rolling wire-byte rate.
- (decision) The coordinator publishes typed, session-scoped lifecycle notifications through an Observer port; the Wails adapter alone maps them to transfer-started, transfer-progress, transfer-complete, transfer-error, and transfer-reset runtime events. The React reducer treats backend notifications as authoritative and ignores mismatched session IDs.
- (decision) Port interfaces are owned where they are consumed. As Phase 1 placeholders become implementations, lifecycle port definitions move to internal/transfer and the stream port is consumed by internal/server; adapter packages implement them. The Phase 1 method semantics and context cancellation are preserved, while the server port gains session-scoped lifecycle callbacks required by FR8-FR10.
