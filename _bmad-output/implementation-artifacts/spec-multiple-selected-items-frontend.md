## Intent

Implement the frontend portion of the parent collection story. It is one shared feature, not an independently released slice. Parent spec and selection contract define all product acceptance requirements.

## Ownership and integration

- Own `frontend/**` except `frontend/wailsjs/**` (generated by backend implementer). Do not edit Go, parent specs, canonical contracts, shared evidence or docs; report required amendments to main. Do not commit, push or bump versions.
- Backend bound methods: `StageTransfers(paths: string[])` returns FileMetadata; `SelectFiles()` returns string[]. Existing `StageTransfer(string)`, SelectFile and SelectDirectory remain. Coordinate generated-binding availability with `/root/implement_multiple_items`; never hand-edit bindings or run Wails concurrently with a frontend suite.
- FileMetadata adds `isCollection: boolean` and `itemCount: number`. Collections have name `N items`, aggregate size, `isDir: false`, `isCollection: true`, count 2..16. Singletons emit false/1. Strictly reject malformed collection metadata; preserve existing valid legacy singleton fixtures/DTOs by treating both new fields absent as singleton, never accepting a partial or inconsistent pair.
- One controller owns draft selection and asynchronous operations; keep paths only in private memory, expose basename-only draft rows for rendering. Copy mutable input arrays, prevent stale chooser admission after cancel/unmount, and preserve existing outcome release/reset and Send Again recovery. Include item kind collection in pending, receipt and summaries.

## Tasks and acceptance

- Implement selection list, native multi-drop and additive native multi-file chooser, keyboard controls, focus return/removal and announcements exactly as the parent contract. Direct single-item selection stays immediate.
- Extend useTransfer, validation, public types/reducer/selectors and App integration for batch stage, repeat and retry. Avoid parallel admissions, avoid calling Stage before Send, reject over-limit append without silently truncating. Any invalid batch keeps a usable list and clear error.
- Update copy registry and views so collection count/ZIP labeling is truthful, including errors and outcomes. Keep Quartz styling, min target sizes, programmatic focus and forced-colors mechanisms. Do not introduce draggable images.
- Add meaningful unit/controller/App tests for empty/one/many/16/17, cancelled or stale chooser, append/remove/focus, duplicates rejected by backend, metadata shape, immutable arrays, exact remembered batch, repeat single-flight, lease-release failure, and cancellation cleanup.
- Add rendered-browser verification for collection controls, keyboard flow, narrow layout and forced colors where existing harness supports it. No fabricated native WebKit observations.
- Add portable, baseline/assertion-validated scoped mutations for high-impact new controller/validation guarantees, with unique full logs; coordinate canonical mutation inventory with main. Do not mutate concurrently with a suite in this checkout.
- Run frontend suite/typecheck only after regenerated bindings are available; report exact results and uncovered behavior. Backend owns full Wails gate; main owns integration review.
