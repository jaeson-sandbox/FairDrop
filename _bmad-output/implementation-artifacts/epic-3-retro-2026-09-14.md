### Aggregate views

#### A1 — Architecture delta: none. Checked and clean.

**Derivation:** non-test `fairdrop/internal/*` imports, extracted per package at `3120590^` and at
`2bb8caf` and compared.

| Package | Imports (both endpoints) |
|---|---|
| `internal/transfer` | *(none)* |

| `internal/network` | `internal/transfer` |

The graph is **identical** before and after an epic that changed 24,300 lines. The domain core
imports nothing internal; every adapter depends only on it. No cycle, no new cross-cutting
dependency, no layering violation. The one sibling-to-sibling edge — `internal/stream` →
`internal/server` — is at the baseline too (`3120590^:internal/stream/archive.go:15`), so it is
inherited rather than introduced.

This is the single strongest result in the retrospective. Twelve sessions, each seeing only its own
story, did not bend the structure once.

#### A2 — Duplication map: three duplicated bodies, one worth acting on

**Derivation:** exact-body comparison of every non-test Go function of six statements or more
(`{scratch}/dupscan.py` over 62 production files). Three hits, total:

- `internal/source/handle_posix.go:121` / `handle_windows.go:193` — `Close()`, 6 statements
- `internal/source/handle_posix.go:154` / `handle_windows.go:209` — `Close()`, 6 statements

Both pairs sit behind build tags, which is why they cannot merge. Idiomatic, not a finding.

- **`internal/source/platform_windows.go:12` (`platformReparsePoint`) and
  `internal/stream/platform_windows.go:19` (`reparsePoint`) — 11 statements, byte-identical.**

This one is a finding. Two packages carry their own copy of the Windows reparse-point check — the
guard that stops a junction reading as an ordinary directory because Go's `FileMode` only models
the subset it names. `internal/stream` cannot import `internal/source`, so the copy is structurally
forced; what is not forced is that **nothing pins the two to agree**. Only the `source` copy has a
test (`internal/source/platform_windows_test.go:116`); `stream`'s has none of its own, and no test
compares them. The reasoning comment explaining why an unrecognised metadata shape must error
rather than return `false` lives only on the `stream` copy — the `source` copy has the logic without
the reason, which is the half more likely to be "simplified".

Failure mode: a junction that `source` refuses and `stream` accepts, on a path the Linux job cannot
even compile. **Pre-existing, not introduced by this epic** — both files exist at `3120590^`, and
the epic touched them once (`9b0e10e`, staticcheck enforcement). Disposition: **defer** with an id.

#### A3 — `internal/transfer/coordinator.go` is the epic's one size candidate

**Derivation:** `git_evidence.py` change volume ranked, then each top file's real structure read.

It is 1,175 lines and grew +389 net across Stories 3.4, 3.6, 3.8, 3.10 and 3.11 — no single session
added much. Only four production files in the repo exceed 600 lines, and this is the largest.
Inside it are eight distinct responsibilities: the diagnostic sink (`:133`), the session resource
ledger (`:197`), `Stage` (`:379`, **213 lines** — the longest function in the codebase),
`AuthorizeClaim`, the unwind path, a six-function bounded-call subsystem (`:746`–`:893`), the
operation lease (`:1009`), the publish lane (`:1053`), and identity generation (`:1127`).

The package already splits its *tests* across five files and its production code across seven, so
the convention for splitting exists and this file simply outgrew its share. The bounded-call
subsystem is the obvious seam: 148 cohesive lines that Stories 3.4 and 3.8 grew together, sitting
beside a `lifecycle.go` of only 314 lines.

Not called a god class: its responsibilities are cohesive around one aggregate and the package's
boundaries are intact (A1). Called a **candidate to split before it grows again** — Story 4.1 will
add to `app.go` and `selection_source.go`, not here, so the next epic is the cheap moment.
Disposition: **defer** with an id.

#### A4 — Two near-identical bounded stop wrappers, with one load-bearing asymmetry

`internal/transfer/coordinator.go:821` (`stopServerBounded`) and `:841` (`stopBeaconBounded`) are
30 lines each and structurally the same; the second's own comment says it "mirrors
stopServerBounded exactly". They differ in their message strings and in one real way: the server
path checks `IsUnquiescent(err)` and returns it as a command failure, the beacon path does not.

That asymmetry is correct — quiescence is a server guarantee — which is exactly why this is
recorded rather than refactored: a helper parameterised over "is this error a command failure?"
would hide the one line that matters. Disposition: **accept**, recorded so a later reader stops
re-flagging it.

Related and **clean**: `callBounded:793` and `callAdapterBounded:854` both carry the
arm-before-launch invariant, and the duplication is guarded —
`internal/transfer/errors_test.go:353` (`TestEveryBoundedCallArmsItsBoundBeforeLaunching`) parses
the source and fails if either drifts. That guard exists because a Windows runner caught the
ordering wrong in Story 3.10 after thirty green local iterations.

#### A5 — Pattern divergence: error construction is consistent; mutation vocabulary is not

**Error handling — clean.** A two-tier convention holds across all 62 production files:
`transfer.NewError` / `transfer.WrapError` (252 uses) for anything that becomes a coded public
state, and `errors.New` / `fmt.Errorf` (109 uses, non-test) only for adapter-local causes that get
wrapped at the boundary. Every `fmt.Errorf` site outside tests is a platform shim or an internal
sentinel. No divergence.

**Evidence vocabulary — divergent.** Each of the twelve stories recorded its mutations, as the house
rule requires, but in four vocabularies: Stories 3.6, 3.9, 3.10, 3.11 and 3.12 write **KILLED**;
3.2 writes "FAIL, named after fix" and "caught"; 3.7 and 3.8 write "passed"/"failed". The result is
a ledger no machine can read: the epic ran on the order of 200 mutations and nothing can count them
or tell a survivor from a kill without a human reading twelve documents.

That matters more than a style nit, because **survivors are recorded in this ledger and matter**:
`evidence-3-2:355` records M4 as **survived**, and the row below it explains why that is correct
rather than a gap — two mutually redundant guards mean neither is individually load-bearing, and
the combined M2+M4 mutation is killed by deadlock. That is exactly the reasoning a reviewer needs
and exactly the reasoning an inconsistent ledger buries. Disposition: **process action**.

#### A7 — Three comments a later story falsified, and one doc comment it orphaned

**Derivation:** absolute claims in production comments ("the one", "the only", "exactly one"),
checked against what the code now contains. Twenty such claims; three are false, all three falsified
by Story 3.11, and one of the three is visible in tool output.

**1. `internal/transfer/types.go:72`** — *"WarnBeaconUnavailable is the one WarningCode this build
produces."* Written by `06119d6` (Story 3.6). `bb90845` (Story 3.11) added `WarnUnportableNames`
**fourteen lines below it**. A reader of the type is told the package has one warning code while
looking at the second.

**2. `internal/transfer/coordinator.go:1160`** — the same claim, and worse, because `bb90845`
inserted `unportableNamesWarning` *between the comment and the function it documents*. The two
comment blocks now run together, so Go attaches the whole thing to the wrong function. Proved by
`go doc -all -u ./internal/transfer`:

```
func beaconWarning() Warning

func unportableNamesWarning() Warning
    beaconWarning is the fixed non-fatal warning for a discovery failure.
```

`beaconWarning` documents nothing; `unportableNamesWarning` documents `beaconWarning`. This is not a
style opinion — it is what the toolchain prints.

**3. `app.go:446`** — *"This is the application-lifetime context and the only one the App stores."*
Written by `387b828` (Story 1.7). `0ebca6d` (Story 3.11, D-097) added
`a.commands, a.stopCommands = context.WithCancel(ctx)` **on the line after the comment ends** — the
second stored context, two lines below the sentence denying it exists.

Every one of these is harmless to the running program and corrosive to the next reader, and the
project leans hard on its comments: they carry the reasoning that makes the guards legible. There
is no gate for this. `gofmt`, `go vet` and `staticcheck` do not read a claim about how many of
something exist, the mutation harness cannot mutate a sentence, and a reviewer sees only the diff's
own hunk — which in all three cases did not include the comment being falsified.

The upstream lesson is specific and cheap: **an absolute claim in a comment is a pin without a
test.** Either write it so a later addition cannot falsify it, or put the count where a test can
read it. Disposition: **fix** (trivial), plus a **process action**.

### Diff-scope review

Three lenses ran over the epic's production Go diff (39 files, +2,645/−325), weighted to the
boundaries between stories. Tests and BMAD artifacts were out of scope for this pass.

**Every lens finding below was re-checked against the primary source before being recorded, and

#### B1 — `acquireInstanceLock` is called by `main()` and by no test. **Confirmed.**

`instance_lock.go:38`. Exactly one call site (`main.go:223`) and no test file references it. The
inner primitive `lockFileExclusive` *is* tested directly (`main_test.go:990`), and
`TestAnUnheldInstanceLockLeavesTheAppUncomposed` takes `held` as an already-decided boolean handed
to `buildApp(held)` — so the function that decides it is never run.

**Mutation:** replacing the whole body with `return func() {}, true` leaves the **entire repository
suite green**, all eight packages. D-088's per-user backstop lock — an owner decision from Story
3.10 — could stop working silently. Disposition: **fix** (a test).

#### B2 — Narrowing the drainer's production call site reintroduces D-042/D-091 silently. **Confirmed.**

`internal/transfer/outcomes.go:64-68` passes `stateStaged, stateClaiming, stateTransferring` to
`acceptTerminal`, so a session whose server dies inside the CLAIMING window still gets a synthesized
failure. `TestTheDrainerMayEndASessionFromEveryStateOneCanBeIn`
(`coordinator_stage_test.go:1186`) looks like the test for this, and is not: it declares its own
`allowed := []sessionState{stateStaged, stateClaiming, stateTransferring}` and hands that literal to
`drainerMayActLocked`. It proves the guard honours whatever it is given — vacuous pattern 1,
self-referential, with the expectation written at the assertion site *as* the value under test.

The test's own comment says so outright. That is honest, and it is still a gap.

**Mutation:** narrowing the production call site to `stateStaged, stateTransferring` leaves
`internal/transfer` green. The regression it would reintroduce is a session showing a QR code for a
dead listener, forever. Disposition: **fix** (a test that drives CLAIMING through `drain`).

#### B3 — All three D-018 response headers are unpinned. **Confirmed.**

D-018 was one of the four release-blocking platform decisions Story 3.10 settled, on 2026-09-12, and
A6 above confirms it was propagated to all four binding documents. The code implementing it has no
test at all.

| Header | Where | Mutation result |
|---|---|---|
| `Access-Control-Allow-Origin: *` on rejections | `handler.go:259` | deleted → `internal/server` **green** |
| `Access-Control-Expose-Headers: Content-Disposition` | `handler.go:280` | deleted → **whole repo green** |
| `Accept-Ranges: none` | `handler.go:285` | deleted → **whole repo green** |

The rejection header is the more interesting failure, because a test *looks* like it covers it:
`TestRejectionsAreIndistinguishable` (`handler_test.go:107`) renders each rejection's headers and
compares them **to each other**, taking the first rendering as the reference. All-missing is exactly
as indistinguishable as all-present, so the test passes either way. Vacuous pattern 1 again, in the
package where the epic's most-cited decision lives.

Consequence if any regresses: a cross-origin receiver page reads every rejection as one opaque
network error — the precise thing D-018 was decided to prevent — or loses the filename off
`Content-Disposition`, or a download manager range-retries a consumed one-shot capability.
Disposition: **fix** (three literal-value assertions).

#### B4 — `StartBeacon`'s unselected path can leak the selection gate undetected. **Confirmed.**

`internal/network/beacon.go:49-53`. The branch releases `m.mu` and the selection gate before
returning `ErrBeaconWarning`. **Mutation:** dropping `m.releaseSelectionGate()` from that branch
alone leaves `internal/network` green — the one test reaching this code asserts the returned error
and never re-acquires the gate afterwards, unlike its sibling test for the "already active" branch,
which does exactly that (`beacon_test.go:325`).

A leaked token is not a degraded path: every later `GetLocalIP` and `StartBeacon` on that Manager
blocks until its caller's context is cancelled, for the life of the process. Disposition: **fix**
(one follow-up acquisition in the existing test).

#### B5 — `resolveAncestorsWith`'s eval-failure branch is unexercised. **Confirmed.**

`selection_source.go:118-121` returns the original `selection` when `filepath.EvalSymlinks` fails,
preserving the source's coded refusal. **Mutation:** replacing that with the path built from a
zero-value `parent` leaves the **whole repo green**. Every test stubs the outer `resolve` field and
bypasses this function, or supplies a filesystem where eval succeeds.

Reachable whenever an ancestor is transiently unreadable between the picker returning and Stage
resolving — a TOCTOU window the function's own comment acknowledges. Disposition: **fix** (a direct
call with a failing eval stub).

#### B6 — A completed transfer's Complete event is dropped if a stop races finalization. **Confirmed by inspection.**

`internal/server/lifecycle.go:650`:

```go
if state == http.StateClosed && !stopping && r.ctx.Err() == nil {
    if tracked, ok := conn.(*finalizingConn); ok && tracked.terminal != nil {
```

`finalizeAfterResponse` records the Complete event on the connection and returns; delivery happens
later, when net/http reports `StateClosed`. If a Cancel or Shutdown sets `r.stopping` or cancels
`r.ctx` in that window, the recorded event is discarded. Every byte reached the receiver and the
sender is told the transfer was cancelled.

The window is narrow and the scenario is not exotic: it is the user pressing Cancel just as the
transfer finishes. The comment above explains why the connection stays *tracked*; it does not
address suppressing an outcome that was already achieved. **What the sender should be told when a
cancel lands after the last byte is a contract question**, not a bug with an obvious fix — Story
3.11's D-035 answered the neighbouring question for a snapshot-less Complete. Disposition: **defer**
with an id; it needs the owner.

#### B7 — A wedged ancestor resolution converts a temporary busy into a permanent one. **Confirmed by inspection.**

`selection_source.go:31-41`. `s.resolving` is cleared only inside the worker goroutine, after
`s.resolve(path)` returns. The caller escapes on `ctx.Done()`; the flag does not. If
`filepath.EvalSymlinks` never returns — an unresponsive network-mounted ancestor, and this repo
provisions native Windows UNC fixtures in CI precisely because that path is real — every later
`Inspect` for **any** path returns `ErrBusy` for the rest of the process.

The comment says "Bound abandoned work to one call per decorator", which is true of concurrency and
not of time. Story 3.7 chose that bound because "an OS filesystem call cannot be cancelled"; the
unexamined case is the call that never comes back. `ErrBusy`'s copy, revised in Story 3.11, now
tells the user to wait or restart — correct advice, and here they would wait forever.
Disposition: **defer** with an id; a time bound on an uncancellable call is a design decision.

#### B8 — `defaults read` can hang before the window exists, on macOS only. **Confirmed by inspection.**

`theme_darwin.go:22` calls `exec.Command("defaults", "read", "-g", "AppleInterfaceStyle").Output()`
with no context and no deadline, from `main()` **before** `wails.Run`. A wedged `cfprefsd` means
FairDrop blocks with no window, no dialog and no log line.

The asymmetry with the Windows sibling is the tell: `theme_windows.go` reads a registry key, which
cannot hang this way, and its comment promises "any failure to read it answers light". The darwin
comment makes the same promise about an *error*. Neither contemplates a hang, because Story 3.10
asked what the value should be and nobody asked what happens if the answer never arrives.
Disposition: **fix** (`exec.CommandContext` with a short deadline).

#### B9 — `publish` spawns a goroutine and a timer per progress snapshot. **Confirmed by inspection.**

`internal/transfer/coordinator.go:1061` routes every event through `callBounded`, which launches a
fresh goroutine and arms a fresh timer per call, and `forwardProgress` calls `publish` once per
accepted snapshot. An observer that stops returning therefore accumulates one abandoned goroutine
per snapshot for the rest of the transfer.

Abandoning a bounded call is deliberate and recorded (D-034, D-049) — Go cannot force a function to
stop. What is not addressed is the difference in *frequency*: the cleanup calls that established the
pattern happen once per session, and `callAdapterBounded` even shares a slot so a second caller
joins the in-flight call rather than starting another. `publish` has no such slot and runs thousands
of times. Disposition: **defer** with an id.

#### B10 — `finalizeAfterResponse`'s defensive branch cannot be reached. **Confirmed; accept.**

`handler.go:201-212` degrades a Complete to a failure when the request context carries no
`*finalizingConn`, commenting that "an alternate transport cannot claim success without observing
finalization." It cannot run: `lifecycle.go:317` always wraps the listener, and `lifecycle.go:340`
does an **unchecked** `conn.(*finalizingConn)` assertion that would panic the connection goroutine
before the `ok` check below could ever be false.

So the real protection is a panic, not the graceful degradation the comment describes. Not worth
changing; worth recording, so a later reader does not count it as live. Disposition: **accept**.

#### Adversarial lens

Eleven findings; three restate B1, B6 and B8 from other lenses, which is signal — three independent
stances reaching the same three places. The rest, verified:

**B11 — D-018's recorded rationale contains a false clause. Confirmed; the behaviour is sound.**
`handler.go:258` justifies the rejection header with *"a status is only ever about a token the
caller already holds (D-018)"*. That is false for the 404 branch, which is reached precisely when
the caller holds a token nobody issued. The lens read this as a capability-token oracle. I do not,
and the reason is the product's own threat model: `copy.ts:61` tells the user *"The transfer is not
encrypted, so someone monitoring this network may be able to observe it."* Anyone positioned to use
a status oracle is already positioned to read the token off the wire in cleartext, so the marginal
disclosure is nil — and a guess against 128 bits learns nothing it did not already know. **The
behaviour stays; the sentence is wrong and should be corrected** to say what is actually true: the
status distinguishes outcomes for a caller who has the URL, and a caller without it learns nothing
a 128-bit guess did not already tell them. Disposition: **fix** (the comment).

**B12 — `buildApp`'s comment names two Windows paths; macOS reaches the same place. Confirmed.**
`buildApp` (`main.go:248`) returns an inert App when the backstop lock is not held, and `main()`
calls `wails.Run` regardless — so a second launch Wails' own lock missed gets a real window where
every command answers `not_ready`. That is deliberate and recorded. What the comment says is that
it happens only on *"the two Windows fallthroughs D-088 describes"*, and Story 3.10 made that
incomplete: `singleInstanceOption` (`main.go:186`) also returns nil on **darwin** whenever
`nativeSingleInstanceLockUsable()` fails its probe (`single_instance_darwin.go:12`), reaching the
same inert window on macOS.

Whether an inert window is the right answer there is the owner's call — exiting silently on a
double-click is what D-088 deliberately chose *not* to do on Windows — but the comment describing
when a user can see it is now wrong. Disposition: **fix** (the comment) and **defer** (the macOS
behaviour question).

**B13 — the instance lock disables itself with no diagnostic. Confirmed.** All three failure
branches of `acquireInstanceLock` (`instance_lock.go:40,49,54`) return `held=true` — no backstop —
and none logs anything. The epic's own convention is the opposite everywhere else it disables a
protection: `singleInstanceOption` logs *"single-instance protection unavailable … launching
without protection"*, and `buildApp` logs when the lock is not held. A locked-down profile
directory or a full disk therefore silently removes D-088's backstop with no forensic trail at all.
One fixed, path-free line closes it (AD-9 forbids the path, not the fact). Disposition: **fix**.

**B14 — `Stop()`'s docstring promises a no-op that a mundane cleanup error breaks. Confirmed.**
`internal/server/lifecycle.go:376` states *"repeating it after either kind of error is still a
no-op."* Tracing `Stop`: `s.unresolved` is cleared only when `active.teardown()` returns nil
(`:421`). After a mundane, non-unquiescent cleanup diagnostic it stays set, so a second `Stop()`
takes the `s.active == nil` branch, finds `teardownFinished()` true and `IsUnquiescent` false, and
falls through to `return unresolved.teardown()` (`:408`) — replaying the same cached diagnostic as
though freshly discovered. The unquiescent case *is* pinned
(`TestARepeatedStopDoesNotUpgradeAnUnresolvedTeardownToSuccess`); the mundane one is not.
No-op in side effects, not in return value. Disposition: **fix**.

**B15 — a slow beacon stop delays the receiver by up to the cleanup bound. Confirmed.**
`AuthorizeClaim` calls `stopBeaconBounded()` (`coordinator.go:631`) while holding the operation
lease and before committing the claim, with the receiver's HTTP request already open.
`AdapterCleanupBound` is 15 seconds. D-024 is cited right there and answers the adjacent question —
an mDNS shutdown that *never returns* must not hang the claim, so the commit proceeds either way.
It does not address the one that returns slowly: on a contended interface the receiver waits, with
no response and no feedback, before the first byte. Nothing in the file discusses receiver-side

## Acceptance verdict

**accepted-with-open-items.** Criteria were **declared** — `epic-3-context.md`'s Requirements &
Constraints and Technical Decisions, plus each story's own acceptance criteria.

All twelve stories are `done`; `pending_stories` is empty, so nothing forces a machine **rejected**.

**What the epic set out to do, it did.** FairDrop is verified by native Windows and macOS runners
with a locked toolchain, builds its own artifacts on each, enforces one running instance with a
per-user backstop, bounds every lifecycle wait with a coded failure, makes a lost or malformed event
visible, reconciles public copy with the states it describes across a five-place cross-language pin,
hardens the directory stream, settles four release-blocking platform decisions, and — new in the
last story — measures its accessibility floor in a real browser instead of reading it out of a
stylesheet. The architecture came through untouched (A1), the error convention held across 62 files
(A5), and all eleven prior retrospective action items are discharged with evidence.

**Why not plain accepted, in one sentence each:**

- One declared requirement is half delivered. "200% text **with text-spacing overrides**" is in the
  epic's inventory, in `DESIGN.md` and in `EXPERIENCE.md` with all four values spelled out, and
  nothing checks any of them (A6).
- A settled decision is unpinned. D-018 — one of the four release-blocking decisions Story 3.10
  closed — is correctly propagated to all four binding documents and implemented by three header
  lines that can each be deleted with the whole repository green (B3).
- Two guarantees are mutable against a green suite: D-088's backstop function (B1) and the drainer
  state that closed D-042/D-091 (B2), the second behind a test whose own comment admits it proves
  only that the guard honours whatever it is handed.

**Not rejected**, and the distinction is real: no story is unfinished, no defect is known-shipped in
a release, and every finding above is either unperformed verification or documentation that the
code outgrew. Nothing found here contradicts what the product does — five of the twelve action
items are comments that drifted away from correct code.

**The pattern worth naming.** This epic's code is in better shape than its prose. Five separate
findings — A7 (three falsified claims plus one orphaned doc comment), B11, B12, B14, B16 — are all
the same shape: the implementation is right and the sentence beside it is stale, incomplete, or
false. In a codebase that deliberately carries its reasoning in comments, and where those comments
are how the next session learns why a guard exists, that is a load-bearing defect class with no
gate. `gofmt`, `go vet` and `staticcheck` do not read a claim about how many of something exist;
the mutation harness cannot mutate a sentence; and in every case here the falsified comment was
outside the diff hunk that falsified it, so no reviewer could have seen it either.

The upstream lesson is one line: **an absolute claim in a comment is a pin with no test.** Either
write it so a later addition cannot falsify it, or put the count where a test can read it — the way
`errors_test.go` already pins the registry, and `TestEveryBoundedCallArmsItsBoundBeforeLaunching`
already pins an ordering claim by parsing the source that makes it.
