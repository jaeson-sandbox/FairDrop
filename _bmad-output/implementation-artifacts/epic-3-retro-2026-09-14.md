### Aggregate views

#### A1 — Architecture delta: none. Checked and clean.

**Derivation:** non-test `fairdrop/internal/*` imports, extracted per package at `3120590^` and at
`2bb8caf` and compared.

| Package | Imports (both endpoints) |
|---|---|
| `internal/transfer` | *(none)* |
| `internal/server` | `internal/transfer` |
| `internal/source` | `internal/transfer` |
| `internal/stream` | `internal/server`, `internal/transfer` |
| `internal/network` | `internal/transfer` |
| `internal/qr` | `internal/transfer` |

The graph is **identical** before and after an epic that changed 24,300 lines. The domain core
imports nothing internal; every adapter depends only on it. No cycle, no new cross-cutting
dependency, no layering violation. The one sibling-to-sibling edge — `internal/stream` →
`internal/server` — is at the baseline too (`3120590^:internal/stream/archive.go:15`), so it is
inherited rather than introduced.

This is the single strongest result in the retrospective. Twelve sessions, each seeing only its own
story, did not bend the structure once.

#### A2 — Duplication map: three duplicated bodies, one worth acting on

**Derivation:** exact-body comparison of every non-test Go function of six statements or more
(`{scratch}/dupscan.py` over 62 production files). Three hits, total:

- `internal/source/handle_posix.go:121` / `handle_windows.go:193` — `Close()`, 6 statements
- `internal/source/handle_posix.go:154` / `handle_windows.go:209` — `Close()`, 6 statements

Both pairs sit behind build tags, which is why they cannot merge. Idiomatic, not a finding.

- **`internal/source/platform_windows.go:12` (`platformReparsePoint`) and
  `internal/stream/platform_windows.go:19` (`reparsePoint`) — 11 statements, byte-identical.**

This one is a finding. Two packages carry their own copy of the Windows reparse-point check — the
guard that stops a junction reading as an ordinary directory because Go's `FileMode` only models
the subset it names. `internal/stream` cannot import `internal/source`, so the copy is structurally
forced; what is not forced is that **nothing pins the two to agree**. Only the `source` copy has a
test (`internal/source/platform_windows_test.go:116`); `stream`'s has none of its own, and no test
compares them. The reasoning comment explaining why an unrecognised metadata shape must error
rather than return `false` lives only on the `stream` copy — the `source` copy has the logic without
the reason, which is the half more likely to be "simplified".

Failure mode: a junction that `source` refuses and `stream` accepts, on a path the Linux job cannot
even compile. **Pre-existing, not introduced by this epic** — both files exist at `3120590^`, and
the epic touched them once (`9b0e10e`, staticcheck enforcement). Disposition: **defer** with an id.

#### A3 — `internal/transfer/coordinator.go` is the epic's one size candidate

**Derivation:** `git_evidence.py` change volume ranked, then each top file's real structure read.

It is 1,175 lines and grew +389 net across Stories 3.4, 3.6, 3.8, 3.10 and 3.11 — no single session
added much. Only four production files in the repo exceed 600 lines, and this is the largest.
Inside it are eight distinct responsibilities: the diagnostic sink (`:133`), the session resource
ledger (`:197`), `Stage` (`:379`, **213 lines** — the longest function in the codebase),
`AuthorizeClaim`, the unwind path, a six-function bounded-call subsystem (`:746`–`:893`), the
operation lease (`:1009`), the publish lane (`:1053`), and identity generation (`:1127`).

The package already splits its *tests* across five files and its production code across seven, so
the convention for splitting exists and this file simply outgrew its share. The bounded-call
subsystem is the obvious seam: 148 cohesive lines that Stories 3.4 and 3.8 grew together, sitting
beside a `lifecycle.go` of only 314 lines.

Not called a god class: its responsibilities are cohesive around one aggregate and the package's
boundaries are intact (A1). Called a **candidate to split before it grows again** — Story 4.1 will
add to `app.go` and `selection_source.go`, not here, so the next epic is the cheap moment.
Disposition: **defer** with an id.

#### A4 — Two near-identical bounded stop wrappers, with one load-bearing asymmetry

`internal/transfer/coordinator.go:821` (`stopServerBounded`) and `:841` (`stopBeaconBounded`) are
30 lines each and structurally the same; the second's own comment says it "mirrors
stopServerBounded exactly". They differ in their message strings and in one real way: the server
path checks `IsUnquiescent(err)` and returns it as a command failure, the beacon path does not.

That asymmetry is correct — quiescence is a server guarantee — which is exactly why this is
recorded rather than refactored: a helper parameterised over "is this error a command failure?"
would hide the one line that matters. Disposition: **accept**, recorded so a later reader stops
re-flagging it.

Related and **clean**: `callBounded:793` and `callAdapterBounded:854` both carry the
arm-before-launch invariant, and the duplication is guarded —
`internal/transfer/errors_test.go:353` (`TestEveryBoundedCallArmsItsBoundBeforeLaunching`) parses
the source and fails if either drifts. That guard exists because a Windows runner caught the
ordering wrong in Story 3.10 after thirty green local iterations.

#### A5 — Pattern divergence: error construction is consistent; mutation vocabulary is not

**Error handling — clean.** A two-tier convention holds across all 62 production files:
`transfer.NewError` / `transfer.WrapError` (252 uses) for anything that becomes a coded public
state, and `errors.New` / `fmt.Errorf` (109 uses, non-test) only for adapter-local causes that get
wrapped at the boundary. Every `fmt.Errorf` site outside tests is a platform shim or an internal
sentinel. No divergence.

**Evidence vocabulary — divergent.** Each of the twelve stories recorded its mutations, as the house
rule requires, but in four vocabularies: Stories 3.6, 3.9, 3.10, 3.11 and 3.12 write **KILLED**;
3.2 writes "FAIL, named after fix" and "caught"; 3.7 and 3.8 write "passed"/"failed". The result is
a ledger no machine can read: the epic ran on the order of 200 mutations and nothing can count them
or tell a survivor from a kill without a human reading twelve documents.

That matters more than a style nit, because **survivors are recorded in this ledger and matter**:
`evidence-3-2:355` records M4 as **survived**, and the row below it explains why that is correct
rather than a gap — two mutually redundant guards mean neither is individually load-bearing, and
the combined M2+M4 mutation is killed by deadlock. That is exactly the reasoning a reviewer needs
and exactly the reasoning an inconsistent ledger buries. Disposition: **process action**.

#### A6 — Spec-to-implementation reconciliation

Checked against `epic-3-context.md`'s Requirements & Constraints and Technical Decisions.

**The pending header decision was made and propagated — clean.** The inventory named "the pending
CORS, `Accept-Ranges`, and `Access-Control-Expose-Headers` decision" and required that settling it
amend contract, architecture, spec and tests together. D-018 settled it on 2026-09-12 and it is in
all four: `docs/fairdrop-architecture.md:124-126`, `docs/fairdrop-spec.md:108,127`,
`internal/server/handler.go:259,275,280,285`, `internal/server/handler_test.go:421,1017`.

**One declared requirement is half met — WCAG 1.4.12 text-spacing.** The epic's inventory requires
"200% text **with text-spacing overrides**", and it is not a loose paraphrase: `DESIGN.md:178` says
"Content containers grow under 200% text **and WCAG text-spacing overrides**", and
`EXPERIENCE.md:275` spells the values out — 1.5× line height, 2× paragraph spacing, 0.12em letter
spacing, 0.16em word spacing. It entered the contract as the fix for `review-accessibility.md`'s
A11Y-08, which named 1.4.12 explicitly.

**Nothing checks it.** Not `styles.test.ts`, not the new rendered suite: no test in
`frontend/src/**` or `frontend/browser/**` applies or asserts any of those four overrides. Story
3.12 delivered the 200% half and not the text-spacing half, and its own I/O matrix is why — the
spec's scenario list names 320 pixels, 200% text, targets and forced colors, and never names
text-spacing. So no story was wrong; the epic's declared requirement is simply half delivered, and
no single story could see that.

This is the retrospective's primary finding. It is also the cheapest to close: the rendered harness
now exists, `style.css` sets `letter-spacing` on three selectors (`:204`, `:215`, `:528`) which is
precisely what a 1.4.12 user stylesheet overrides, and a text-spacing case is a few lines beside
`doubleTextTokens` in `frontend/browser/accessibility.test.tsx`. Disposition: **fix**, routed as an
action item.

#### A7 — Three comments a later story falsified, and one doc comment it orphaned

**Derivation:** absolute claims in production comments ("the one", "the only", "exactly one"),
checked against what the code now contains. Twenty such claims; three are false, all three falsified
by Story 3.11, and one of the three is visible in tool output.

**1. `internal/transfer/types.go:72`** — *"WarnBeaconUnavailable is the one WarningCode this build
produces."* Written by `06119d6` (Story 3.6). `bb90845` (Story 3.11) added `WarnUnportableNames`
**fourteen lines below it**. A reader of the type is told the package has one warning code while
looking at the second.

**2. `internal/transfer/coordinator.go:1160`** — the same claim, and worse, because `bb90845`
inserted `unportableNamesWarning` *between the comment and the function it documents*. The two
comment blocks now run together, so Go attaches the whole thing to the wrong function. Proved by
`go doc -all -u ./internal/transfer`:

```
func beaconWarning() Warning

func unportableNamesWarning() Warning
    beaconWarning is the fixed non-fatal warning for a discovery failure.
```

`beaconWarning` documents nothing; `unportableNamesWarning` documents `beaconWarning`. This is not a
style opinion — it is what the toolchain prints.

**3. `app.go:446`** — *"This is the application-lifetime context and the only one the App stores."*
Written by `387b828` (Story 1.7). `0ebca6d` (Story 3.11, D-097) added
`a.commands, a.stopCommands = context.WithCancel(ctx)` **on the line after the comment ends** — the
second stored context, two lines below the sentence denying it exists.

Every one of these is harmless to the running program and corrosive to the next reader, and the
project leans hard on its comments: they carry the reasoning that makes the guards legible. There
is no gate for this. `gofmt`, `go vet` and `staticcheck` do not read a claim about how many of
something exist, the mutation harness cannot mutate a sentence, and a reviewer sees only the diff's
own hunk — which in all three cases did not include the comment being falsified.

The upstream lesson is specific and cheap: **an absolute claim in a comment is a pin without a
test.** Either write it so a later addition cannot falsify it, or put the count where a test can
read it. Disposition: **fix** (trivial), plus a **process action**.

story in this epic. Everything Epic 3 changed that only a human can see is recorded there as

camera (row 14), and a screen reader hearing any of it (rows 10 and 11).

That list is the honest statement of this epic's limit. It built the machinery to prove what a
machine can prove, and it did not — and structurally could not — observe the rest.
