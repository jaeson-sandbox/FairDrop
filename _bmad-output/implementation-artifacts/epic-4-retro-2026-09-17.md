## Findings

### F1 -- 582 lines of production Go shipped outside any story (high)

**Source.** `git diff --stat 56a2a1f 69c1f94 -- '*.go' ':!*_test.go'`: 6 files, 370 insertions, 212
deletions. `54fc84f` ("drop a sprint-status key for a story that never existed").

Between Story 4.2's merge and the release, a branch carrying no spec created
`internal/transfer/bounded.go` (195 lines, new), rewrote 233 lines of
`internal/transfer/coordinator.go`, and reworked `selection_source.go` (+104). For comparison, Story
4.2's own production footprint across the whole story was **171 insertions and 27 deletions**. The
unspecced branch changed more production code than the story that had a spec, an I/O matrix, three
review layers and an evidence file.

The sprint key that would have tracked it -- `4-3-close-the-retrospective-deferrals-and-release-v0-3-0`
-- was created and then deleted, correctly, on the grounds that no spec or evidence backed it. That
deletion removed the record of the gap rather than the gap.

None of this is defective code: it is covered by tests, it passed CI on three platforms, and the
`bounded.go` extraction is a genuine improvement. What it lacks is the thing every other change in
this project has -- a spec stating intent before the code, and a review that read the diff against
it.

**Disposition.** Defer, with a decision needed. **Upstream lesson.** "Close the deferrals and cut a
release" is story-shaped work. Either it gets a story, or `bmad-build` needs a sanctioned lightweight
path for it -- but silently doing it on an unnamed branch is the option that should stop.

### F2 -- a declared acceptance criterion that nothing could enforce (medium; closed)

**Source.** `epics.md` Epic 4, criterion 5: "any label this story introduces ... enters
`EXPERIENCE.md` by stable key first". `EXPERIENCE.md:92-94`. D-119 in `deferred-work.md`.

Story 4.1 introduced three labels. Their registry rows were added during review, by reading, not
because anything failed -- and the criterion says *first*. The end state satisfies the criterion;
the sequence did not, and no gate existed to notice either way. The cross-language **error**
registry is pinned in eight places; the **copy** registry was pinned in none.

**Disposition.** Fixed, after the epic closed and on the owner's instruction to make the scope call:
`copy.test.ts` now reads the Voice and Tone table and pins it both ways -- every row must name a real
leaf and quote its string exactly, and every leaf outside `label` and `unit` must have a row. Six
mutations, all killed. D-119 discharged. Carried on PR #2 rather than inside the epic, which is
itself an instance of F1's pattern, recorded here rather than excused.

### F3 -- coordinator.go is still the largest production file (medium)

**Source.** 1175 lines at `baa52ec`, 1008 at `1a12072`. Next largest production file:
`internal/server/lifecycle.go` at 784.

The Epic 3 retrospective excluded splitting `coordinator.go` as "a refactor that deserves a story not
also fixing ten unrelated things" (`epics.md`, Story 4.2 section). Roughly a third of it then
happened anyway, inside F1's unspecced branch. The file is still 29% larger than the next production
file and still the one every lifecycle change touches.

**Disposition.** Defer -- the Epic 3 action item stands, now partially done. **Upstream lesson.**
When a story excludes a refactor and the work then happens anyway, amend the exclusion rather than
let it be outgrown silently.

### F4 -- IdleView.tsx more than doubled (low-medium)

**Source.** 328 lines at `1a12072`, up 184 net this epic -- a 128% growth, now the second-largest
frontend production module behind `useTransfer.ts` (347).

`BrowseControl` is a general ARIA menu-button widget -- roving tabindex, Home/End, Escape, focus
return, blur handling -- living inside a view module. `EXPERIENCE.md` calls it the product's first
floating surface. A second one will either duplicate this or force the extraction then.

**Disposition.** Accept for now; the widget has exactly one caller and extracting on speculation
would be the worse trade. Recorded so that a second floating surface triggers extraction rather than
a copy.

### F5 -- the story boundary: checked and clean

**Source.** `selection_source.go:142-151`, `app.go:288`, `selection_source.go:66`.

The one place the two stories could have collided is the root package: Story 4.2 added 104 lines to
`selection_source.go` while Story 4.1 rewrote `app.go`'s `chooseWith`. They do not interact.
`chooseWith` produces a path and `selectionSource.Inspect` consumes one -- sequential, not
overlapping. More usefully, Story 4.2's two new error constructors
(`selectionResolutionCancelled`, `selectionResolutionBoundElapsed`) reuse `ErrCancelled` and
`ErrSetupFailed` rather than inventing codes, so Story 4.1's eight-place registry move did not miss
one. Both name no path, as AD-9 requires.

This is recorded as checked, not as absent.

### F6 -- commit subjects carry no story ids (low)

**Source.** `git_evidence.py` output: every one of 37 commits returned `stories: []`.

The retrospective's own tooling could not attribute a single commit. The convention in this project
is a prose subject; the tool matches story ids. Neither is wrong, but together they mean per-story
attribution is manual, and a commit spanning two stories cannot be detected at all.

**Disposition.** Process lesson. **Upstream lesson.** Either put the story id in a trailer, or accept
that this tool's attribution is unusable here and stop reading its `stories` field as evidence.

### F7 -- a vacuous test shipped inside the story that wrote it (medium; closed in-story)

**Source.** `326b7dc`; `frontend/browser/accessibility.test.tsx:460`.

Story 4.1's 640x480 browser case asserted the open menu's `getBoundingClientRect().bottom` stayed
within `window.innerHeight`, and could not fail: opening the menu focuses its first item, Chromium
scrolls a focused element into view, and a viewport-relative coordinate compared against the viewport
measures that scroll. A mutation pushing the menu 600px down the page passed at `bottom = 479.95` in
a 480px window with `scrollY = 723`.

It matters beyond its own fix. Every earlier vacuity in this project was found by mutating production
code; this one was insensitive to the property it named, so only mutating the test's *environment*
exposed it. It was written by the same session that reviewed it, which is the gap
`review-your-own-fixes-too` names.

**Disposition.** Fixed in-story: two scroll-invariant measurements, three mutations, all killed.

## Behavior verification

Partial, and the gap is named rather than papered over.

- **Exercised.** `wails build` succeeds and produces `fairdrop.exe` with no binding drift. The browse
  menu was exercised in real Chromium through the browser suite -- opened, keyboard-navigated,
  measured at 320px, 640x480, 200% text, forced colors, and the 44px floor. Chromium is the engine
  WebView2 runs, so for Windows this is the runtime, not a simulation.
- **Not exercised.** The built binary was not launched and no native file or folder chooser was
  opened by hand, so the `chooser_failed` path and the menu-to-native-dialog handoff are proved by
  tests and fakes only. `docs/release-policy.md` makes manual observation optional for this project;
  this records that the option was taken, not that the path was verified.
- **Not reproducible here.** WebKit/macOS does not move focus to a clicked `<button>`, which is
  invisible to both jsdom and Chromium. The menu's blur handling was reasoned about for that case and
  pinned by tests that stage the focus move explicitly, but no macOS WebKit run confirms it.

- *Exactly one browse control where two were, drop zone still leading.* Met. `IdleView.tsx:162` is

- *macOS `NSOpenPanel` in one step.* Not delivered, and **not required**: the epic declares it

No blocking finding stands unresolved and both stories are `done`, so the machine verdict is not
`rejected`. It is not clean `accepted` either: F1 is a real governance gap with production code
behind it, and F3 carries an Epic 3 item forward a second time.
