## Findings

### Architecture delta — checked, clean

Derived from the import graph of every non-test Go file in the range.

- No package under `internal/` imports the Wails API. The coordinator (`internal/transfer`) imports no concrete adapter. Both boundaries the architecture declared are intact, and both are enforced by greps recorded in the story specs rather than by convention alone.
- The adapter graph is hub-and-spoke with no cycles: `source`, `network`, `server`, `qr` each depend only on `transfer`.
- **Two adapter-to-adapter edges exist and both are correct.** `internal/stream` imports `internal/server` because `server` *owns* `PayloadPort` (`internal/server/server.go:51`) and `stream` implements it, asserted at compile time by `var _ server.PayloadPort = (*Payloads)(nil)` (`internal/stream/archiver.go:82`) — the provider importing the consumer's port is the ports-and-adapters shape, not a violation of it. `internal/stream` also imports `internal/source` to re-validate the item from an opened descriptor (`archiver.go:121`), which Story 1.9's Code Map records as deliberate: one inspector, reached twice.

*Disposition: accept. Recorded so a later retro does not re-flag either edge.*

### Size growth — checked, one file worth watching

`internal/transfer/coordinator.go` is the largest production file at 776 lines, and the `transfer` package totals 5,945 lines across six non-test files. The package was split deliberately during the epic — `outcomes.go` (363) took the drainer's event meaning in Story 1.6 and `lifecycle.go` (198) took Cancel/Shutdown/reset — so the growth was managed rather than accreted. 776 lines for the component that owns all lifecycle state is large but not a god class, and no other production file exceeds 500.

*Disposition: accept, with a note that a further split is the right response if 1.6's successors (Story 3.4) add more to it.*

### Test-to-production ratio — 2.04 : 1

18,558 test lines to 9,087 production lines across the range. The single largest file in the epic by net churn is `internal/stream/archiver_test.go` (+1,624), testing a 498-line production file — 3.3 : 1 for that pair.

This is high, and it is the project's stated standard rather than an accident: `AGENTS.md`'s "Testing standards, learned the hard way" records eight defects that shipped past a green suite, and the mutation bar exists because of them. The ratio is evidence the standard was applied, not evidence of over-testing.

*Disposition: accept.*

### Pattern divergence — one real instance

`internal/stream/archiver.go` is named for a job it no longer does. Its package doc describes turning "one validated staged item into payload bytes for a single authorized HTTP response" (`archiver.go:1-4`), its types are `Payloads` and `payload`, and it implements `server.PayloadPort`. Nothing in it archives. The name survived the Story 1.3 replacement of the `Streamer` contract by `PayloadPort`, which `deferred-work.md` records as a note rather than a rename.

Consequence is orientation, not behaviour: an agent pattern-matching this codebase reads the filename as the module's job, and this one lies. It is also the file a directory-zip story (2.2) will reach for by name and find the wrong thing in.

*Disposition: fix — rename to `payload.go` with its test, owned by Story 2.2, which is the next story to touch it.*

### Duplication map — checked, no accidental duplication

The two cross-language mirrors are deliberate and each is pinned:

- The error-code registry exists in `internal/transfer/errors.go` and `frontend/src/transfer/errors.ts`, kept in step by a cross-language test that fails in `internal/transfer` naming all four places a code must be added.
- DTO validation exists in Go (at the source boundary) and again in TypeScript (`validation.ts`), which is defence in depth against a forged webview event rather than a duplicate: Story 1.8's reducer treats correlation as a security property because Wails' frontend `EventsEmit` notifies same-window listeners before Go ever sees the event.

No case was found of the same rule implemented twice by accident.

*Disposition: accept.*

## Behavior verification

Runtime behaviour **was** exercised, by the user, on the real binary — the first time in the epic that happened.

Observed: a real file staged; the QR code scanned by a phone on the same Wi-Fi; the download completed; the colours reported correct. This discharges the two Epic 1 verification criteria that no automated check could reach — "one real nearby-browser download" and the QR encoder meeting an actual camera, which Story 1.5a had never had.

Three defects were found by that run and fixed inside it: a focus ring that stayed painted after a mouse click (`[data-focus-target]:focus` on nodes made click-focusable by `tabindex="-1"`), a drop target that looked clickable and did nothing, and a cancellation summary with no status treatment sitting below the selection controls.

**Not exercised:** no screen-reader pass, and no render at 320 CSS pixels, 200% text, or forced colors. The accessibility floor is proved against the stylesheet text and the DOM, never against a rendered layout. Recorded in `deferred-work.md` under `3-2-automate-reproducible-cross-platform-verification`.

### Cross-story seams — six findings, every one verified against source

These are the boundaries no single coding session saw both sides of. Each was re-checked against the primary files before routing.

**S1 — The app offers a folder path it always refuses, with a message saying folders are allowed.** `internal/source/source.go:114` returns `Kind: ItemFile` on its only success path and answers every directory with `ErrPathUnsupported`; nothing in the composed binary ever produces `ItemDirectory` (`types.go:22`), so `IsDir` (`coordinator.go:420`) is permanently false. Meanwhile `app.go` binds `SelectDirectory`, `IdleView` ships a "Select Directory" button, `copy.idle.instruction` reads "Drop one file or folder.", and `path_unsupported`'s fixed copy reads "FairDrop can use regular files and folders only." A user who takes the folder path this build offers is refused by the very sentence that says folders are fine. Each story was right alone — 1.1 correctly refuses folders in an Epic 1 build, 1.7 correctly binds the chooser Epic 2 needs, 1.9 correctly renders registry copy written for the finished product — and together they ship a broken promise. Every `isDir` branch downstream (`state.ts:232`, the ZIP note in StagedView) is unreachable dead code until Epic 2.
*Disposition: fix now. The most user-visible defect in the epic.*

**S2 — A successful transfer can be announced as "Transfer canceled."** `outcomes.go:161-165` publishes an unknown-total zero snapshot for a `Complete` that arrives without one, deliberately, so a port defect "does not downgrade a success". `state.ts:232-236` refuses exactly that snapshot for a file. The complete is dropped, the view stays in Transferring, the backend's three-second reset lands, and `announce.ts:188` routes transferring→plain-idle to `cancel-won`. Two defences in depth, each sound alone, producing an outcome strictly worse than the one the Go comment was guarding against. The same end state has a second, production-reachable door: `app.go` drops an event on a nil context, an `emit` panic or an unroutable kind and counts it in `undelivered`, which `grep` shows is read only by `app_test.go`.
*Disposition: fix now, and it unifies three existing deferred entries (1.7's inert counter, 1.9's control-less terminal outcome, 1.10's cancel-won routing).*

**S3 — `Warning.Code` is the whole registry in Go and one literal in TypeScript, and the mismatch destroys the session rather than the warning.** `types.go:53-56` types it `ErrorCode`; `types.ts:11-14` narrows it to `'beacon_warning'` and `validation.ts:62` rejects anything else — which makes `parseFileMetadata` return null for the *entire* acknowledgement, cancelling a perfectly good session and showing "The transfer stopped before FairDrop finished sending" for a transfer that never started. `main_test.go`'s cross-language pin covers `transferErrorCodes` only, so adding a second warning code on the Go side stays green.
*Disposition: fix now — constrain the Go type or widen the pin to cover warning codes.*

**S4 — The `beacon_warning` announcement is unreachable, and the banner sits outside the focused node.** Recorded during Story 1.10 as `accepted`; the seam review shows it is worse than recorded. `announce.ts:151-153` fires only when the warnings array grows while already `staged`, which no reducer path produces — `metadata` is written once by `stage-succeeded` and never replaced. The reachable case routes to the Staged heading, and the warning `<aside>` is nested inside the packet, outside both the focused node and any live region. On the one machine state the warning exists for, a screen-reader user is never told discovery is down.
*Disposition: upgrade from accepted to fix — the recorded note claimed the row was merely unreachable, not that the warning is silent.*

**S5 — Go's twelve public messages never reach a user, and ten of them are pinned by nothing.** `errors.go:117-130` and `errors.ts:34-48` hold byte-identical copies; every frontend path substitutes its own registry copy, so Go's strings are display-dead. `main_test.go:130-180` pins the code list and two of the twelve messages, so editing any of the other ten changes nothing on screen and no test notices.
*Disposition: defer to Story 3.5, which already owns the copy registry.*

**S6 — Progress coherence is implemented three times with two contradictory strategies.** `outcomes.go:329-347` repairs (clamps NaN, zeroes an unknown total), `validation.ts:78-92` rejects, `selectors.ts:80-87` repairs again — and the selector's clamps can never fire because the rejecting layer runs first. The rejecting layer also couples the frontend to an exact float expression: `validation.ts:90-91` requires `percent` to equal `100 * bytesSent / totalBytes` within 8 ULP, so rounding percent for display on the Go side would silently drop every progress event. Separately, `parseFileMetadata` runs twice per Stage — including a second `atob` and full PNG chunk walk of up to 2 MB — and the reducer's copy fails differently from the controller's, leaving the UI in Pending with no error and no announcement.
*Disposition: defer to Story 3.4, which owns lifecycle robustness.*

### Seams checked and found clean

Recorded so a later retrospective does not re-derive them: the five event names end to end (`ports.go` ↔ `app.go` ↔ `types.ts` ↔ the five literal `subscribe` calls); the `Event` JSON shape against the per-kind payload table for all five kinds; the terminal error allow-lists (identical four-code sets); the twelve-code registry, pinned; all seven `focusTargets` carried by a view; `bytesSent > totalBytes` unproducible given the read cap, the delivered-length recheck and the staged-size pin; and `FileMetadata` field-by-field across Go, TypeScript and the validator.

## Acceptance verdict

**accepted-with-open-items.** Criteria were **declared** — the epic's requirements inventory and each story's acceptance criteria.

The epic's central claim is demonstrably met, and for the first time by observation rather than by test: a real file was staged, a phone scanned the QR, and the download completed. Ten of ten stories are `done` with no `pending_stories`, the architecture boundaries hold under mechanical check, and every seam that could be checked mechanically agrees end to end.

It is not a clean **accepted**, for three reasons stated plainly. Two shipped defects are user-visible — the folder path that is offered and refused, and the successful transfer that can be announced as a cancellation. A third, the single unreproduced `internal/transfer` failure, is bounded below 1-in-800 but unexplained, and its evidence was destroyed by the verification gate itself. None is a blocking defect for what Epic 1 set out to do, which is why this is not **rejected** — but calling it **accepted** would be reporting more confidence than the evidence carries.

## Open questions

- The single unreproduced `internal/transfer` failure. ~806 executions across seven configurations (parallel, single-CPU, under load, `-race`, 720 in-process iterations) produced no reproduction, and the original evidence was destroyed by a gate that piped through `tail -3`. Cause unknown; bounded below 1-in-800.
- Whether the announcement contract actually holds for a screen reader. Every routing-table row is unit-proved, but "each transition is announced exactly once" is ultimately an observation about NVDA or VoiceOver.
