## Findings

### F1 -- the verification was the weak part, and it repeated a pattern recorded hours earlier (high)

**Source.** `evidence-5-1…md` section "The `go doc` check was vacuous"; the Blind Hunter layer.

The story's evidence presented `go doc -all ./internal/transfer` as the second of three faithfulness
checks and called the set "stronger than 'the tests still pass'". `go doc -all` prints only exported
symbols and every one of the 194 moved lines is unexported, so the check was insensitive to the
entire story. Zero moved symbols appear in the compared output. It could not have failed.

What makes this the finding of the epic is the timing. Story 4.1 found a structurally identical
vacuity in its own browser measurement, and the lesson was written into the project's notes as a
named pattern *hours before* this check was authored. Knowing the pattern did not prevent
re-committing it, because the check was never tested against the thing it claimed to protect.

**Disposition.** Fixed in-story; `go doc -all -u` run since (a benign 36-line const-regrouping diff).
**Upstream lesson.** A verification command is a claim like any other, and the only thing that
establishes it is mutating what it covers and watching it fail. Recording a pattern is not a control.

### F2 -- three review agents shared one working tree, and one left a mutation in it (medium)

**Source.** Edge Case layer's out-of-band note; `git status` at the time showed
` M internal/transfer/session.go` with `hold` gutted to `_ = held`.

A review subagent mutated production code to test a guard and did not restore it. It was caught by a
second layer, reverted, and never reached a commit -- `6ff98d5` predates it and both origin and CI
held correct code -- so the blast radius was zero. But this is the second occurrence of concurrent
agents colliding on one tree in this project; the first produced a committed red tree.

Notably, one of the three layers used throwaway `git worktree`s unprompted and left the tree clean,
which is the fix.

**Disposition.** Defer to process. **Upstream lesson.** Parallel reviewers that may mutate should be
given worktrees, not the working tree.

### F3 -- the mutation sample was sized per concern, and the gap was in the file with two declarations (medium)

**Source.** Verification Gap layer; mutations W1/W2 in `evidence-5-1…md`.

The story ran "six mutations, one per concern" across four files, then claimed "every new file has at
least one mutation killed in it, so none of the extracted code is decorative". `warnings.go` holds
*two* functions and only `beaconWarning` was exercised. `unportableNamesWarning` turned out to be
executed by no test at all: wrong code and wrong registry entry both shipped green.

Sampling by concern hid exactly the declaration the sampling missed.

**Disposition.** Fixed (D-121, pinned on branch). **Upstream lesson.** Size a mutation battery by
declaration, not by file or concern, and state the denominator.

### F4 -- the commit-attribution gap recurred unchanged (low)

**Source.** `git_evidence.py` on `b8ea881..21efa61`: 0 of 11 commits attributed.

Epic 4's F6 recorded this and raised action item 27 (decide whether commit subjects should carry
story ids, or stop reading the tool's `stories` field). The item is still `open` and the gap
reproduced exactly.

**Disposition.** The existing action item stands. It is cheap and it keeps costing a manual step.

### F5 -- the governance rule held on its first exercise (positive)

**Source.** `AGENTS.md:207`; the story's artifact set.

Epic 4's F1 produced the rule that production changes need a story. Story 5.1 was the first work
under it and it held: spec, three review layers, evidence file, and 582 lines of unspecced
production code did not happen. The rule's carve-out also did real work -- when the review found two
things needing `_test.go` edits, they went on a *separate commit on the same branch* under the
test-only clause rather than being smuggled into the story or deferred indefinitely.

**Disposition.** Accept. Worth recording that a process change from the previous retro was exercised
and worked, so a later reader knows it was tested rather than merely written.

### F6 -- the zero-test-edit bar paid for itself, and the way its cost was paid is reusable (positive)

**Source.** The story's acceptance criteria; commits `6ff98d5` and `df2aabe`.

Forbidding test edits is what made faithfulness directly checkable: pure deletion, 194/194 lines
verbatim, both reproduced independently by two layers. It also meant two genuine gaps could not be
fixed in the story. Splitting the branch into "the move" and "the pins the move exposed" preserved
both properties at once.

**Disposition.** Accept, and reuse. **Upstream lesson.** When a story's bar forbids the very edit a
finding needs, a second commit on the same branch is usually better than a deferral.

## Behaviour verification

No runtime behaviour was exercised, and none should have been: the epic's premise is that nothing
observable changes. What stands in for it is stronger than a smoke test -- the diff into
`coordinator.go` is pure deletion, all 194 removed non-blank lines reappear character-for-character
in the new files, and `go doc -all -u` differs only by const grouping. `go test -race` passes on 8
packages.

Not exercised: the built binary, the frontend suites, `wails build`. A same-package file move with no
exported-API change cannot move a binding.

## Acceptance verdict

**accepted-with-open-items.** Criteria were **declared** (five Given/When/Then blocks in
`epics.md`), not profiled.

- *Zero `_test.go` edits.* Met. The story's own diff touches no test file; the pins landed on a
  separate commit.
- *`go doc -all` byte-identical.* Met as worded. Recorded as vacuous evidence (F1); the covering
  command shows a benign 36-line shape change.
- *Under 830 lines, no declaration of the four regions.* Met: 790. The criterion had to be reworded
  first -- as written it said "contains none of", which could never pass, since `session` appears 47
  times as a type reference.
- *Each file declares one concern and carries its comments.* Met after review, which found the two
  files lacking the header `bounded.go` establishes as the precedent.
- *Full story ceremony.* Met: spec, three layers, evidence file.

No story is unfinished and no blocking finding stands, so the machine verdict is not `rejected`. It
is not clean `accepted` either: D-122, D-123 and D-125 are real findings recorded and not fixed, and
F1 is a verification failure that reached a merged evidence file before a reviewer caught it.
